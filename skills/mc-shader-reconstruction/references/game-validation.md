# Minecraft 游戏内验证

先按[模型验收标准](acceptance.md)记录用户要求或默认标准并完成源模型对照；本页补充目标游戏运行时的验证，结果须与桌面检查分别记录。

最终画面、兼容性和帧率以目标 Minecraft ModSDK 运行时为准。先检查实际加载的 shader、材质、后处理 pass、uniform 顺序和资源包版本，再按独立测试命令运行模型效果。

## 画面与模型验证

- 使用与源模型可比较的构图检查整体轮廓、比例、部件位置和主要负空间；用不同静态观察方向检查缺失构件、包围体裁切和坐标错误。
- 分开观察静态模型和动画：固定模型视角核对动作，冻结动作核对几何。检查指定的关键姿态和循环边界。
- 在目标分辨率和窗口比例下检查完整画面、裁切、材质颜色、法线和边缘稳定性。
- 核对开始、重播、提前停止、正常结束、资源重载和卸载等生命周期行为。

## 性能记录

在相同场景、分辨率、画质、帧率上限及其他后处理条件下先记录基线，再运行 shader。记录设备、画质条件、观察方式、样本长度和游戏 FPS 或帧时间。手动观察应标为估测，不能把桌面 GPU 时间换算成游戏帧率。

测试失败时先核对资源包是否部署、pass 是否进入 render order、参数名和顺序是否一致，以及当前游戏是否重新加载资源。交付时区分已在桌面检查、已在游戏检查和仍需实测的内容。
