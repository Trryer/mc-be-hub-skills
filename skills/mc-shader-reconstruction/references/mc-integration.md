# 独立模型 Shader 的 MC 接入

本参考说明如何在网易 Minecraft ModSDK GLSL 项目中接入一个独立的全屏模型 shader 测试。具体配置、资源命名和生命周期以活动项目为准，先检查 manifest 与相邻后处理实现。

## 定位项目接入点

| 责任 | 定位目标 |
| --- | --- |
| 全屏顶点输入与 UV | 使用 Position/UV0 的 vertex shader |
| 模型 SDF、虚拟相机与着色 | fragment shader 及引用函数 |
| 参数契约与后处理定义 | pass 配置、render_order 和参数列表 |
| shader 与 pass 的关联 | 实际部署的 post-process material |
| 客户端启停与测试生命周期 | 本地生命周期控制对象 |
| 测试命令到客户端事件 | 对应 server/client handler |
| 对象创建与卸载 | handler 的构造与 Destroy 调用链 |

可从项目已有的 post_process.json、postprocess.material、Handler_Client.py、Handler_Server.py 和相似测试模块开始，按项目清单确认真正加载的资源路径。

为新效果分配独立文件前缀、pass、material、事件、模块、类、命令和日志名。沿用现有对象创建与卸载方式，确认客户端/服务端对象都在正确生命周期创建和清理。

## 静态 pass 与参数

如果项目采用资源包静态声明 pass，可沿用“默认关闭、初始化参数、运行时启用、到期关闭”的方式。是否静态注册应由目标项目的现有做法或验证结果决定。

配置文件按项目的 JSONC 规则编辑。将 pass 加入 render_order 并关联实际材质。参数按声明顺序打包；配置、运行时代码和 GLSL uniform 的名称、顺序、分量数与单位必须一致。新增或调整参数后重新核实目标引擎的打包规则。

典型的一组 vec4 可包含局部时间、屏幕宽高和曝光；这是结构说明，不是所有项目或 pass 的固定布局。对照目标 shader 的实际读取方式设置运行时值。

## 测试生命周期

1. 重播时结束旧轮次并更新本轮标识，确认 pass 已加载。
2. 读取真实屏幕尺寸并上传初值；参数更新和开启成功后再标记为 active。
3. 定时回调携带本轮标识，避免旧回调停止新一轮。
4. 按项目可用的实时钟更新经过时间和屏幕尺寸，到期后关闭 pass。
5. 关闭失败保留可观察日志并按项目方式重试；销毁时关闭 pass 并注销监听。

如果运行时参数只在逻辑 tick 更新，不要声称获得每个渲染帧的新时间。游戏主线程阻塞时，定时器或 tick 的收尾也要等线程恢复。

## GLSL 与交付检查

沿用目标项目的 multiversion、引擎 include、UV 和 fragment 输出约定，使用游戏版本支持的 GLSL 语法。桌面 GLSL 包装结果不能代替 MC 编译和运行检查。新增静态资源或脚本后按项目要求重新进入世界或加载资源包。

检查资源关联、render order、uniform 顺序、启动/停止、提前 stop、重复启动时旧回调、屏幕尺寸变化、参数失败、关闭重试和对象卸载。交付独立测试命令、资源重载步骤和实际验证范围。
